# FlowForge — 전체 확정 요구사항 및 개발 기준선

> **상태:** 사용자와 단계별로 확정한 요구사항. 향후 변경은 별도의 명시적 승인 필요.  
> **기준:** v0.1.3 → 신규 통합 구현. 이 문서는 기능 요구사항이며 구현 완료를 뜻하지 않는다.

## 0. 비전과 원칙

- VSCode 확장 프로그램. **Rust 코어**가 데이터 무결성·경로 탐색·검증·시뮬레이션을 담당하고 VSCode 확장/웹뷰는 TypeScript/JavaScript로 UI/호스트 통합을 담당한다.
- AI 채팅 UI는 구현하지 않는다. AI와 사람은 동일한 **텍스트 기반 `.flow.json`** 파일을 읽고 수정한다.
- 사용자의 조작 편의성과 미려하고 일관된 디자인 우선. 노드가 아니라 **프로그램 로직 설계**를 표현한다.
- 논리 구조(노드·포트·간선)와 시각 구조(위치·크기·경로)는 구별한다. **시각 배치 변경은 실행 의미를 바꾸지 않는다.**
- **22 px 고정 격자**: 블록 좌표와 크기·포트·경유점·경로의 모든 좌표는 정수 격자 칸 기반. 경로는 수평/수직만. 확대/이동 후에도 정확히 정렬.
- 기존 파일 호환성과 손실 없는 편집, 실수로 인한 덮어쓰기 방지.

## 1. 캔버스/편집 UX

### 1.1 생성 — 혼합 방식
1. 왼쪽 팔레트에서 드래그해 생성; 블록 배치는 고스트 미리보기와 충돌 안내.
2. 빈 공간 더블클릭 → 블록 검색 메뉴 → 생성 즉시 **제목 인라인 편집**.
3. 기존 연결선 호버 시 표시되는 **+**를 눌러 블록 삽입; `A→B`를 `A→새 블록→B`로 변경, 조건/루프의 출력 의미가 모호할 경우 선택 요청.
4. 팔레트에서 배치했을 때는 제목 편집을 강제하지 않음.

### 1.2 블록 조작
- 블록 드래그는 격자 칸 단위. 충돌 시 **이동 거부** (주변 블록 자동 이동 금지).
- 크기는 격자 칸 단위로 수동 조절, 최소 크기 적용. 정확한 미리보기 표시.
- 블록 속성은 **인라인 편집 + 오른쪽 속성 패널** 모두 지원.
- 블록 본문은 **제목 + 핵심 조건식/처리식** 표시; 상세 설명은 패널에서 확인.
- 빈 공간 드래그는 **사각형 영역 선택**. 선택 사각형과 일부라도 겹치면 선택됨.
- Ctrl+클릭 선택 추가/제거, Ctrl+A 전체 선택, Ctrl+C/V 복사/붙여넣기, Ctrl+D 복제, Delete 삭제.
- 복사 시 선택한 블록들 **사이의 내부 연결선만** 복사; 새 고유 ID 발급.
- 다중 이동 중 하나라도 다른 블록과 충돌하면 **전체 이동 취소**. 외부 연결은 유지.
- 그룹은 *시각적 묶기*이며 접기/펼치기 지원; 하위 차트와 구분. 그룹 이동·복사·색상.
- Undo/Redo는 사용자 한 동작을 하나의 트랜잭션으로 취급. VSCode **재시작 후에도** 이력 유지, `.flowforge/`에 별도 저장.
- 빈 공간 드래그는 선택, Space+드래그 또는 중간 마우스 버튼으로 팬. 휠 스크롤, Ctrl+휠 확대/축소, 화면 맞춤, 미니맵은 옵션.

### 1.3 포트·화살표
- **스마트 연결 포트**: 블록 유형에 따른 자동 포트. 호버/선택 시만 표시.
- 포트는 블록 경계 격자 교차점에 위치. 변경 가능한 시각 위치가 논리적 포트 ID를 변경하지 않음.
- 포트 드래그 → 다른 블록의 유효 포트 연결. 연결 대상 후보 강조.
- 화살표는 **격자선 위 수평/수직 직각 경로만** 사용. 블록 관통 회피, 적절한 우회.
- 자동 경로 + **사용자 지정 수동 경유점 유지**; 경유점도 격자 스냅.
- 경로 선택/조절, 연결선 호버 `+` 삽입, Undo 가능.
- Flow(실행 순서) / Data(값 전달) 포트를 모두 지원하며 종류와 색상으로 구분.

## 2. 블록과 실행 의미

### 2.1 블록 종류
- `start`: 진입점, Flow output `next`만.
- `end`: 종료점, Flow input `in`만.
- `process`: Flow `in/next`, 사람용 `description`과 시뮬레이터용 `expression` 분리.
- `condition`: Flow `in/true/false`, 평가식과 True/False의 의미 고정.
- `io`: Flow `in/next`, 선언된 입력/출력 동작.
- `function`: Flow `in/next`, 실제 소스 함수에 연결; 연결된 C 코드를 직접 실행하지 않음.
- `loop`: Flow `in/body/exit`, 조건에 따른 반복.
- `subflow`: Flow `in/next`, 별도 `.flow.json` 파일 참조; `Step Into/Over/Return`.
- `conversion`: 상이한 Data 타입 연결 시 사용자 명시적 형변환.
- 확장 후보: 상태 전환, 이벤트, 병렬 처리, 인터럽트, 타이머, Break/Continue.
- **자유 연결 + 스마트 블록**: 블록 자유 배치, 실행 의미는 타입·포트로 결정. 자유 순환 연결과 Loop 블록 **모두 허용**.

### 2.2 포트 규칙
- `kind=flow|data`; `direction=input|output`; Data 포트에 명시적인 `dataType`.
- Flow는 Flow끼리, Data는 Data끼리, output→input만 연결.
- Flow output 기본 1개 연결, Flow input 여러 경로 합류 가능.
- Data output은 여러 input으로 분배 가능, Data input 기본 1개 공급원.
- Data **동일 자료형만 직접 연결**. 변환하려면 `conversion` 블록이 필요함.
- 초기 타입: `bool`, `i32`, `u32`, `f32`, `f64`, `string`.
- Data 간선은 실행을 유발하지 않고 값만 전달. 값이 아직 생성되지 않으면 `Uninitialized`.
- 실행·분기는 Flow 연결과 의미가 정의된 포트로만 결정.

## 3. 화면/디자인
- **미니멀 하이브리드** 블록 디자인: 차분한 사각 카드 + 필요한 유형만 도형/아이콘/색상 구분.
- **FlowForge 전용 다크 테마** 고정. VSCode 테마 자동 연동하지 않음.
- 왼쪽 블록 라이브러리, 가운데 격자 캔버스, 오른쪽 속성 패널. 패널 접기 가능하고 좁은 화면에서는 자동 숨김; 사용자가 다시 열 수 있음.
- 선택/연결/패널에만 **짧고 은은한 애니메이션**. 드래그 격자 위치 이동에는 애니메이션 금지. reduced-motion 존중.
- 선택은 파란 테두리, 오류는 붉은 상태, 시뮬레이션 실행은 민트 강조. 상태 중첩 시 오류 표시가 소실되지 않아야 함.
- 상단 도구 모음(되돌리기/다시실행/저장/검증/실행/맞춤 등), 하단 격자·배율·선택/저장 상태.
- 도구는 컨텍스트에 맞게 최소 노출, 단축키는 VSCode 관습에 가깝게 설정.

## 4. 하위 차트와 탐색
- 하위 차트 **새 파일 생성과 기존 파일 연결** 모두 지원.
- 별도 `.flow.json` 파일 참조; 다른 곳에서 재사용 가능. 진입점·종료점 명시.
- 하위 차트 더블클릭해 별도 탭 열고, 상단 breadcrumb로 상위 차트로 복귀.
- 그룹은 실행 의미에 영향을 주지 않으며 하위 차트와 독립적임.
- 잘못된 파일 참조·재귀 참조 등을 검증/시뮬레이션에서 처리.

## 5. AI와 파일 협업
- 기존 VSCode AI 도구가 직접 텍스트 파일을 읽고 편집; FlowForge에는 채팅 없음.
- 외부 변경 시 **미저장 편집이 없으면 자동 갱신**. 미저장 편집 중이면 **시각적 Diff**.
- AI/사용자 변경 충돌은 **노드 단위 선택·병합** (서로 다른 변경은 병합 가능). 변경을 임의로 덮지 않음.
- 새/삭제/변경 노드와 엣지, 배치 변경을 구분해 보여줌.
- 파일을 저장할 때 외부 변경 충돌을 재확인. 임시 파일→같은 파일시스템 원자적 교체를 지향(파일시스템/VSCode Remote별 제한 테스트).
- **알 수 없는 JSON 필드는 보존**. 의미를 알 수 없는 블록은 실행을 거부하고 알림.
- 파일 형식/검증과 로직 검증을 구분. 임시로 미완성 차트라도 저장 가능해야 함.

## 6. 로직 검증기
- **사용자 수동 요청에만 로직 검증 수행**; 입력 중 자동 전체 검증 금지.
- 최소 파싱은 로딩에 허용. 전체 검증은 명령/버튼으로 호출.
- 검사: ID 중복, 포트 참조·연결 방향·종류·자료형, 조건분기 누락, 도달불가 노드, 잘못된 하위차트, 자유 순환, Loop 경로, 격자/블록 충돌, 데이터 미초기화 등.
- 오류 블록 강조 + **VSCode Problems 패널** 표시. 항목 선택하면 해당 블록으로 탐색.
- 오류/경고/정보의 심각도 구분; 무한 루프는 의도된 구조일 수 있으므로 경고.
- Quick Fix는 사용자 명시 승인 시에만 수행.

## 7. 시뮬레이터
- **수동 흐름 확인 + 변수/조건식 기반 실행 모두**.
- Step Forward/Back, Run/Pause, breakpoint, watch 변수, trace, 최대 실행 단계 한도.
- Subflow의 Into/Over/Return, 입력·출력과 실행 스택, 반복/재귀 가드.
- 실제 펌웨어/C 코드 실행이 아니라 지원하는 표현식만 안전하게 해석. 지원하지 않는 표현식은 조용히 무시하지 않고 오류 표시.
- 데이터의 마지막 계산값과 미초기화 상태를 명시적으로 구분.

## 8. 소스코드 ↔ 노드 연결
- **함수 전체 또는 선택 코드 범위**에 노드 연결.
- 노드→소스 `Go to Source`, 소스→노드 `Reveal in FlowForge`.
- 소스는 **옆 편집기**에서 열기. 기존 탭/레이아웃은 강제로 닫지 않기.
- 코드 변경 시 차트 자동 수정 금지. **변경 여부·연결 끊김 상태만 표시**.
- 상대 파일 경로, 언어, 심볼, 소스 범위, 선택 당시 내용 해시 등을 기록하여 줄 이동 시 재탐색.
- 연결을 찾지 못하면 사용자가 재지정할 수 있음.

## 9. 스키마 v2
- 파일 확장자 `.flow.json`, `schemaVersion:2`, `documentId`, `revision`, `name`.
- 최상위 `nodes[]`, `edges[]`, `layout{gridSize,nodes,edges,groups}`, `variables[]`, `bindings{}`, `extensions{}`.
- 노드는 고유 `id`, `type`, `title`, `description`, `expression`, `ports[]`; 포트에는 고유(노드 내) `id`, `kind`, `direction`, Data 포트 `dataType`.
- 간선은 고유 `id`, `kind`, `source{nodeId,portId}`, `target{nodeId,portId}`.
- `layout.nodes[id]`는 정수 격자 칸의 `x,y,w,h`와 `portPositions`.
- `layout.edges[id]`는 `routingMode=hybrid`, 정수 격자 `waypoints[]`.
- 로직과 화면을 같은 파일 내 분리. 사용자 지정 경유점은 레이아웃에 저장.
- `.flowforge/history/`에 문서별 영속 작업 이력, `.flowforge/backups/`에 필요시 마이그레이션 백업.
- 파일 읽기/파싱과 데이터 검증은 별도 계층. 미완성 조건분기는 저장 가능, 전체 검증에서 경고.
- 구버전 파일은 자동 **분석 후 사용자 승인으로 변환 저장**. 원본 백업; 애매한 분기 의미는 추측 금지.

## 10. 구현 단계 (전 범위)

| 단계 | 목적 | 핵심 완료 조건 |
|---|---|---|
| Phase 0 | 기존 소스/파일 분석, v2 형식·호환 계층 | v1→v2 변환, 백업, 정상/오류 샘플 테스트 |
| Phase 1 / v0.2 | 편집기 기반 | 격자·스마트 포트·직각 경로·수동 경유점·충돌 금지·혼합 생성·크기 조절 |
| Phase 2 / v0.3 | 복잡한 편집 | 다중 선택·복사·그룹 접기·하위 차트·영속 Undo/Redo |
| Phase 3 / v0.4 | 외부 파일 협업 | 변경 자동 반영, 시각 Diff, 3-way 노드 충돌 관리, 안전 저장 |
| Phase 4 / v0.5 | 검증/시뮬레이션 | 수동 Rust 검증, Problems, Step/Run, Flow/Data, 반복·하위차트 |
| Phase 5 / v0.6 | 코드 연동/마무리 | 함수/범위 연결, 옆편집기 탐색, 변경 추적, VSIX 설치·업데이트 검증 |

## 11. 필수 테스트/완료 조건

- 노드·포트·경유점의 모든 좌표가 22px 그리드 교차점, 모든 화살표 직각 경로.
- 블록 이동과 크기 변경은 다른 블록과 겹치면 전부 거부.
- 선택된 블록만 복제하고 내부 연결만 복제, ID 중복 없음.
- 유효한 구형 파일의 승인 마이그레이션, 백업, 의미가 불명확한 정보 보존/보고.
- 재시작 후 Undo 복구, 외부 파일 변경 후 무단 덮어쓰기 없음.
- 검증은 수동 실행, 오류를 캔버스+Problems에 함께 표시.
- 자료형 불일치 연결 거부, 변환 블록 사용 시 자료형 검사.
- 루프 최대 단계 제한과 하위 차트 호출/복귀.
- 코드 범위 연결 후 줄 이동/파일 수정 감지.
- Node/Rust 단위 테스트와 VSCode Extension Host 통합 테스트; Windows VSIX 실 설치, 명령·Activity Bar 노출 확인.
- Rust 바이너리가 제공되지 않거나 호스트에서 실행 불가하면 일부 기능은 제한될 수 있으나 **허위 완료 표시 금지**.

## 12. 확정 사항과 구현 현실

- 이 문서는 요구사항 **기준선**이며 실제 작업 결과나 테스트 통과를 주장하지 않는다.
- 추후 기능의 축소·변경은 사용자와 별도 협의한다.
- 0.1.3은 레거시 v1 (`version`, `title`, `nodes[x,y,...]`, `edges[from,to,label]`) 데이터를 사용하므로 정확한 필드별 매핑과 조건 분기의 레이블 해석을 검토해야 한다.
