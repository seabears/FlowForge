# FlowForge — 통합 요구사항 기준선 및 릴리스 검증표

> 기준 날짜: 2026-11-22 · 최신 소스 비교 대상: v0.8.0  
> **이 문서는 요구사항 목록이며, 항목에 적혔다고 구현되었다는 뜻은 아니다.**  
> 판정: `확정`(사용자 요구), `제안`(미승인), `미구현/미검증`(구현 증거 부족).  
> 최신 사용자 결정이 옛 문서/설명과 충돌하면 최신 결정 우선.

## H. 빌드·검증 게이트 — **매 버전 강제**

1. `REQ`: 현재 사용자 요구와 위 항목을 비교하여 **새 요구/변경/폐기된 정책**을 먼저 문서 갱신한다.
2. `TRACE`: 각 변경에 `REQ-ID → 파일/함수 → 테스트 → 결과`를 연결한다.
3. `STATIC`: JS/TS 문법, VSIX 매니페스트·버전·파일 구성, JSON 형식 검사.
4. `UNIT`: 모델/라우팅/잠금/선택/포트 호환성/검증/시뮬레이션 자동 테스트.
5. `INTERACTION`: 실제 드래그/포커스/우클릭/마우스 이동/연결선 포트 중심을 UI 레벨에서 검증. 소스 문자열 포함 여부 검사만으로는 **동작 검증으로 인정하지 않는다**.
6. `REGRESSION`: 최신 조작 정책(우클릭 범위선택, 좌클릭 팬, Ctrl+A 블록+연결선, Q 잠금, Space 없음)을 매 빌드마다 검사.
7. `DATA`: 사용자가 제공한 문제가 발생한 `.flow.json`과 정상 샘플 모두로 저장→재로드→Undo/Redo 확인. 원본을 자동 덮어쓰지 않는다.
8. `RELEASE`: Windows VSCode Extension Host와 실제 설치에서 확인할 항목을 따로 추적한다. 수행하지 못하면 **미검증**으로 명시한다.
9. `STOP`: 요구사항 위반, 회귀 테스트 실패, 렌더링 실패가 확인되면 **완료**로 표시하지 말고 수정 또는 알려진 문제로 명시한다.
10. 릴리스 보고에는 요구사항 준수표(통과/실패/미검증), 변경 파일, 테스트 로그, 알려진 제약을 포함한다.

## I. v0.7.9 소스 사전 점검 결과 (이번 검사 범위)

- 확인한 기존 요구사항 파일: `docs/FlowForge_FULL_REQUIREMENTS.md` — 초창기 기준선이며 최신 변경사항 일부 누락.
- 현재 소스 패키지 `FlowForge-v0.7.9-source.zip`의 Node `.test.js` **8개 실행 통과** (모델, 시뮬레이션, 포트, 최근 파일, 우클릭 이동, 연결 진단, 캔버스 선택, 기능).
- **주의:** 이는 일부 Node 테스트에 불과하며 Windows VSCode 실제 설치, 브라우저 마우스 드래그 통합, 전체 요구사항 준수 판정은 완료되지 않음.
- 미구현·미완료 가능성이 있는 기존 범위(예: Rust 코어 실제 사용, 12개 기획 기능, 차트 비교 나란히 보기)는 개별 검증이 필요하므로 완료로 표시하지 않음.
- 기존 기준선의 `Space+drag` 팬 및 `Dark-only` 규칙은 최신 사용자 결정과 충돌하여 이 문서의 최신 정책으로 대체.
